# OSG wishlist: что нужно в open-steamgate для счастья PIA

**Дата:** 2026-10-05
**Контекст:** PIA (ABAP-native coding agent на базе ZLLM-V2) должен жить внутри OSG. Ниже — пожелания к OSG, отсортированные по потребителю. Всё проверено по текущему дереву `~/dev/osg-adt-abap` (0.4 in progress).
**Сопроводительный документ:** `2026-10-05-zllm-for-pia-assessment.md` (карта переиспользования ZLLM→PIA)

---

## Что уже хорошо (чтобы вишлист был честным)

- **Store-seam** `zcl_osd_adt_host=>store( )` из ABAP без HTTP: `READ, WRITE, CHECK, ACTIVATE, CHECKRUN, PARSE, SEARCH, OBJECT, PACKAGE(S), LIST, HISTORY, REVISION, SYSTEM`. `ACTIVATE` синхронно ждёт publish в шаге. Это уже 80% dev-бэкенда PIA.
- **ADT-фасад** с checkruns / abapunit / classrun (F8) / xref / search / DDIC — и та же поверхность, что на SAP: один HTTP-адаптер на обе системы.
- **Всё есть файл** (abapGit-формат, контентно-адресуемые build'ы), git-дерево как рабочий каталог.
- APC/AMC (веб-терминал жив), jobs/daemons, WAIT-rollout, dev-only gate, `zcl_osd_git` (fetch/clone на ABAP с vendored zlib abapGit), Docker одной командой.
- ABAP Unit в CI/Test Explorer; gogen на горизонте.

Дальше — чего не хватает, по убыванию боли.

## P0 — без этого PIA в OSG не заводится / калечится

### W1. ✅✅ HTTPS-проба ПРОЙДЕНА (2026-10-05, живой инстанс)
**Результат:** `cl_http_client` из ABAP внутри OSG → `POST https://api.anthropic.com/v1/messages` → **401 `invalid x-api-key`** (ожидаемо без ключа): TLS, заголовки, тело, чтение ответа — всё работает. Остаток: таймауты и семантика 429/5xx/retry при реальной нагрузке. Детали и скрипты: `~/dev/pia/osg-probe/`.

### W2. `DELETE` (и явный `CREATE`) в store-seam
Node-side `ObjectStore` уже умеет `create`/`delete` (`tools/osd-store.mjs`, watcher даже бампит счётчик на WRITE/CREATE/DELETE), но в `COMMANDS` списка destination их нет. Без `DELETE` агент не может откатить собственное неудачное создание — а «создал, увидел, удалил» — это половина coding-loop.
*Форма:* добавить в `COMMANDS`/`CAPABILITIES` `CREATE` (type/name/package/description) и `DELETE` (type/name), семантика как у ADT-роектиров в port-map section 3.

### W3. Запуск ABAP Unit из ABAP
Сегодня юниты запускаются только снаружи (Test Explorer → ADT HTTP). Для PIA-в-OSG нужен in-process путь: store-команда `RUN_TESTS(object)` или класс рядом с `zcl_osd_adt_unit_object`. Результат — структурированный: класс/метод, pass/fail, сообщение, длительность.
*Почему P0:* верификационный цикл «написал тест → активировал → прогнал» — ядро PIA; ходить loopback-HTTP изнутри своей же системы — сирость и лишний session-менеджмент.

## P1 — определяет качество агентского цикла

### W4. Fast path для новых объектов (уже спроектирован, P4 из dev-API)
Cold build 30–350 с на итерацию агента — непереносимо (агент делает десятки итераций). Warm 0.5–1.5 с — отлично. Прайм 11–17 с уже eager, платится один раз. Просьба — подтвердить приоритет P4 с оговоркой «это нужно не только ABAPiti, но и PIA: разница между секундным и минутным feedback-loop агента».
*Бонус:* правило «новый standalone объект без зависимостей» — ровно паттерн агентских итераций (тест-класс для существующего класса).

### W5. ~~Read-only `READ REPORT`~~ → ✅ отвечено самим разбором кода (2026-10-05)
`READ REPORT` реализован (transpiler-runtime, читает `REPOSRC.data`, `sy-subrc = 4` если нет, опция `state` игнорируется). REPOSRC наполняется **при загрузке build'а/генерации**: transpiler отдаёт INSERT'ы (TADIR + REPOSRC), `osd-batch-inserts.mjs` их батчит; store `WRITE` в REPOSRC **не пишет** (`osd-store.mjs` таблицу не упоминает).
**Следствие для PIA:** `READ REPORT` видит только последнюю опубликованную генерацию; неактивный `WRITE` невидим, и даже после `ACTIVATE` REPOSRC обновится лишь после конца шага. Поэтому read-путь в OSG — строго store `READ`, `READ REPORT` — только «последнее активное» (и это надо запомнить как известную семантику, не как баг). На SAP semantics другая (READ REPORT читает активную версию — совпадает по сути). Задача закрыта.

### W6. Однозначный контракт завершения активации (→ P0)
**Обновление 2026-10-05 (фидбек OSG-коллеги):** ACTIVATE может откладывать публикацию до конца шага — значит цикл «активировал → тут же запустил тесты» **внутри одного ABAP-вызова** без явного перехода между шагами не работает. Нужен контракт: либо явный step-transition из ABAP (WAIT-подобный roll-out), либо ticket + событие/статус «live». Это не UX-пожелание, а корректность verification-loop PIA.

### W7. Явный контракт «активная vs неактивная ревизия»
`build/inactive/active` overlay уже есть, `HISTORY`/`REVISION` в seam есть. Пожелание: стабильный контракт + **diff между ревизиями** (или хотя бы список изменённых объектов) — это готовый `git_diff`-инструмент для PIA без внешнего git.

## P2 — для полноты ABAP-мира и совместимости

### W8. FUGR/FUNC как writable-типы
«FUGR has no source», создание — P6 в dev-API плане. Не блокер MVP (PIA пишет классами), но «разрабатывать произвольный ABAP» без FM нельзя — половина legacy-кода живёт в FUGR. Всегда cold — ок, агент переживёт (W4 сделает терпимым).

### W9. Корпус байт-паритета abapGit-формата
Приложение abapGit в OSG не запустится (GUI/SALV/dynpro — и не надо), но **формат общий**, и это надо зафиксировать тестом: round-trip SAP↔OSG через git для типов, которые пишет PIA (CLAS, INTF, PROG, INCL, DDLS, DEVC; потом FUGR/DDIC). Спайки уже были («vsp-i7's abapGit spike») — оформить в постоянный conformance-корпус, чтобы PIA-записи в дереве OSG читались abapGit-ом на настоящем SAP и наоборот.

### W10. Read-only фасад классических репо-API (дальше W5)
`DDIF_*`-читалки (tabl/data element/domain), `RS_*`-фрагменты, где-used. Это же снимает потребность в SAP-only ветке у half of ZLLM-тулзов и даёт abapGit-headless шанс. Альтернатива where-used — уже существующие ADT `xref/closure`/`xref/readers` — просьба держать их полными для агентских сценариев («кто зовёт этот метод»).

### W11. SMW0-подобное хранилище или «allowed root» для конфига PIA
ZLLM держит `.env` в bin-таблице/SMW0/файлах. В OSG — dataset-sandbox с allowed roots: достаточно документировать рекомендованный root для конфигов/сессий агента (и чтобы он переживал recycle).

## Мелочи для счастья

- **W12.** Bootstrap PIA из git одной командой: `zcl_osd_git` уже fetch-only — идеально для «pull свежего PIA в дерево OSG» (generation N+1 ставится без abapGit-приложения). Пример-демо в доках — и self-hosting-сторителлинг готов.
- **W13.** Долгие шаги в APC-сессии: LLM-вызов 30–120+ с внутри APC-обработчика веб-терминала — подтвердить, что сессия и memory выживают (на SAP — выживают; ZLLM_05 это уже доказывает там).
- **W14.** `timestampl`-точность и `GET TIME STAMP` в трейсе — тривиально, но session-аудит PIA на этом стоит.
- **W15.** Позже поиграть с OSGo (gogen): PIA, скомпилированный в один бинарник — «agent harness без сервера». Не блокер, но красивая глава в истории self-hosting.
